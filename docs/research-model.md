# Research model

A course book needs a course, a university, and a degree. A topic book names a subject and does not ask for a university course guide. Evidence rules are the same for both: the model is not a source, claims need corroborated public sources, and verification is not skipped. Local sources are optional. With none, a course book still continues through course discovery into source discovery, where the client may record public sources it actually opened. A topic book with local sources none, skipped, or available may record those same public sources. It does not look for a university course guide, and writing stays unavailable.

User files improve course fit: syllabus emphasis, terminology, symbols, problem style, labs, and exam patterns. They do not replace the official guide or authoritative literature, and they are not rewritten as the book.

`local_sources.status` is `UNKNOWN`, `NONE`, `AVAILABLE`, `IMPORTED`, or `SKIPPED`. It is a field on the project, not a new project state. `NONE` and `SKIPPED` do not block discovery and do not weaken evidence rules.

Intake records a candidate. It does not finish research.

A stored public source stays `DISCOVERED` and `PENDING`. The client can check a page it has already opened. The server does not fetch that page. A year, title, or ISBN that disagrees with the stored citation is stored as a conflict, and classification stays `PENDING`. Two opened pages that agree on author, title, and year record bibliographic identity only. That identity is not scientific authority and it is not proof of a claim. The client may mark whether the stored course guide cites the source. The server does not infer that mark, and a source that is not cited stays in the bibliography. After public sources exist, status reports how many are pending, conflicting, and not cited by the stored course guide. Writing a release stays unavailable.

A draft is not a release. After public sources exist, status tells the client to store an opened excerpt before a longer draft sentence. The server does not fetch that URL. Excerpt text is untrusted data. A draft claim may cite the excerpt. On a course book the excerpt's source still cannot be a year, title, or ISBN conflict or a source the guide does not cite. A topic book still does not need a university guide. A draft paragraph belongs to one blueprint section and cites a stored excerpt. An empty section stays empty and renders as a gap. A course-book paragraph may cite an open supplement the guide does not list, and the draft labels it as an open supplement. Pirate or unauthorized copies are not recorded. A Rust problem is checked only after three passing runs. A numeric answer is two_witnesses only when two stored excerpts come from different public sources, and that is not verified. `studium_book_next` returns the next tool call for the draft: record a source, store an opened excerpt, write a missing section paragraph, record or check a problem, or render. It does not ask what to do next when that step can be done from open sources or from sources already given, and it does not release the book. A computation stores the expression and the reported result and is accepted only when the server evaluates that expression again. A match is replayed, not verified, and it is not absolute truth. `corpus_started` may pass only when every blueprint section has a supported paragraph, and that check does not release the book. `corpus_sufficient`, `blueprint_accepted`, `authoring_complete`, `verification_passed`, `reviews_current`, `release`, and `release_intact` stay unimplemented. The client stores a blueprint of section ids and titles. For a course book those titles come from the stored guide, and the blueprint does not verify that guide or store factual claims. A claim is draft text plus public source ids. The model is not a source. A claim is rejected when a cited source is missing, has a stored year, title, or ISBN conflict, or, on a course book, is not marked as cited by the guide. A topic book may cite its public sources and does not require a university guide. Claims stay drafts. `studium verify` returns blockers and does not move the book to `RELEASED`. `studium render` writes a DRAFT book: front matter, blueprint chapters, a problem part, appendices (including a source audit of each paragraph as two_witnesses, replayed check, single excerpt, or unchecked), then the bibliography. Empty pieces stay visible gaps. A section may hold several paragraphs, and each substantive paragraph cites a stored excerpt. Unchecked prose appears only in that DRAFT and is labeled unchecked. Greek letters are translated into LaTeX. `studium_paragraph_replace` rewrites a paragraph in place. A section that cannot get a second independent open excerpt or a replayed check is blocked, and the next step is render. A YouTube transcript the client extracted and a Wuolah note the user already opened stay unverified candidates; the video file is not downloaded and the catalog is not fetched. A source whose license forbids this use, as with OpenStax, is rejected. The DRAFT `.tex` includes the blueprint and the claims that passed the support check. It compiles a PDF when `tectonic` or `pdflatex` is on `PATH`. If neither is installed, the `.tex` is still written and no PDF file is invented. `local_sources` stays unchanged.
